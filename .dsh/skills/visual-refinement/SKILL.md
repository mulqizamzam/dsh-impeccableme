# Visual refinement

Improve a real interface by addressing the highest-value visual problem first.

## Procedure

1. Inspect the target screen and existing styles/tokens/components. Establish the current visual language and the user's intended tone.
2. Find the dominant issue: weak hierarchy, inconsistent spacing, typography, low contrast, excessive containers, poor density, unclear alignment, inconsistent states, or unhelpful motion.
3. Choose a small number of changes with explicit rationale. Do not redesign the entire screen to solve a local defect.
4. Preserve accessibility, readable line length, meaningful contrast, responsive behavior, and familiar interaction patterns.
5. Avoid defaulting to generic gradients, decorative cards around every region, tiny low-contrast copy, arbitrary border radii, or motion that adds no feedback.
6. If implementation is authorized, edit the smallest relevant set of files, follow local conventions, and run meaningful checks.
7. When a browser/preview is available, compare before and after at relevant viewport sizes. Otherwise state that visual verification remains pending.

## Output

State the main design issue, evidence, recommended or completed changes, intended effect, responsive/accessibility considerations, and verification result.
