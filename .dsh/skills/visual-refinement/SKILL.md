# Visual refinement

Improve a real interface by addressing the highest-value visual problem first.

## Procedure

1. Inspect target screens, styles, tokens, and components. Establish the visual language and intended product tone.
2. Find the dominant issue: hierarchy, spacing, typography, contrast, excess containers, density, alignment, state consistency, or unhelpful motion.
3. Choose a few changes with explicit rationale. Do not redesign an entire screen to solve a local defect.
4. Preserve accessibility, readable line length, contrast, responsive behavior, and familiar interaction patterns.
5. Avoid generic gradients, decorative cards around every region, tiny low-contrast copy, arbitrary radii, and motion without feedback value.
6. If implementation is authorized, edit the smallest relevant set of files and run meaningful checks.
7. Compare before and after at relevant viewport sizes if a browser is available. Otherwise mark visual verification pending.

## Output

State the main issue, evidence, proposed/completed changes, intended effect, responsive/accessibility considerations, and verification result.
