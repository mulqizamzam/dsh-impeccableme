# Project context

Establish durable product facts before proposing a solution.

## Procedure

1. Inspect repository instructions, README, routes, primary screens, domain types, tests, and existing product/design documents. Use only host tools actually available.
2. Summarize the product's purpose, primary users, core jobs, business constraints, platform requirements, and relevant technical constraints. Separate explicit facts from inferences.
3. Identify the most important unknowns. Ask a focused question only if an unknown materially changes the solution; otherwise state a reversible assumption.
4. Separate durable product truth from surface-specific visual direction.
5. Record evidence locations for material claims. Do not invent user research, analytics, requirements, or stakeholder decisions.
6. When authorized, write a concise brief to the location the user specifies. Inspect existing documentation before proposing an overwrite.

## Output

Provide a short context brief, evidence references, assumptions, unanswered questions, and the next recommended step.
